# kyouzai — 授業用 Web 教材を作る

このスキルは、単一の HTML ファイルで動く授業用の教材を、**ひな形から作り、独立した計算と自動テストと実ブラウザで確かめてから**渡すための手順です。
テーマは毎回先生が決めます。年間計画がなくても、テーマと時間があれば作れます。

同じフォルダにあるもの：

| ファイル | 役目 |
|---|---|
| `template.html` | ひな形。データ（問題・用語・ページ・モデル・シミュレーター）を書きかえるだけで1本の教材になる |
| `regression-template.js` | jsdom の確認スクリプトのひな形。禁止事項・データ・計算の検証・通し・先生用・保存・小テスト |
| `check-browser.mjs` | 実物の Chrome で全ページをたどり、5つの画面の大きさで画面写真と問題点を集める |
| `verify-calc.md` | 計算の検証のやり方と例 |

## 1. 最初に確かめること（足りなければ聞いて止まる）

| 項目 | 例 | 聞かずに決めてよい既定値 |
|---|---|---|
| テーマ（**必須**） | 「超音波で距離を測る」 | なし。なければ聞く |
| 科目・学年 | 電子計測制御・3年 | 工業高校の生徒向け |
| 時間 | 45分×1回 | 45分×1回 |
| 型 | 問題演習／スライド＋シミュレーター／体験（ミッション） | 導入 → しくみ → ミッション → 練習 → 小テスト → まとめ |
| 小テスト | あり・10問・10分 | あり（分野ごとに2〜3問、8〜10分） |
| 配る場所のフォルダ名 | `oto` | テーマの短い英語かローマ字 |

**先生に聞いて止まるのは、次のときだけ。** それ以外は既定値で進め、報告で何を決めたかを書く。
- テーマや授業の狙いが分からない
- モデルに選択肢があり、どれを選ぶかで教える中身が変わる（例：理論の式と、現実に近い式）
- 外へ送る（提出の通信）・音声やカメラを使う・ファイルが 300KB を大きく超える
- 既存の教材を変える、公開する（push する）

## 2. 共通ルール（毎回守る）

**動作の条件（Chromebook の Chrome）**
1. 単一 HTML。CSS・JS・画像（SVG・data URI）を全部中に入れる。**外から何も読まない**（Web フォントも CDN も使わない）
2. フォントは端末にあるものだけ：`"BIZ UDPGothic","Hiragino Sans","Noto Sans CJK JP","Noto Sans JP","Yu Gothic UI","Meiryo",system-ui,sans-serif`（ひな形の `--f-body`）。読みやすさは、大きさ・太さ・行間・余白で出す
3. **レスポンシブが基本**。16:9・16:10・4:3 の Chromebook、縦のタブレット、スマートフォンで崩れないこと。広い画面は「本文＋右の用語欄」、狭い画面は1列で、用語欄は「用語」ボタンの引き出しにする
4. **シミュレーターの描画だけは縦横比を保って拡大縮小する**（ひな形の `mountSim`）。図形をゆがめない
5. タップが前提。押せる物は 44px 以上。**ドラッグだけでしかできない操作は作らない**（−／＋ボタンかキーを必ず付ける）。ホバーに頼らない
6. 軽く作る：1ファイル 300KB まで。アニメーションは見えていないときに止める。`prefers-reduced-motion` に従う
7. 通信なしで最後まで動く。提出の通信は例外で、先生が決めたときだけ（送れなければ「文章をコピー」に切りかえる）
8. ブラウザの `confirm` / `alert` / `prompt` は使わない（Classroom のサンドボックスで常に失敗する）。ひな形の `ask()` / `tell()` を使う

**見た目と文章**
9. **ライトモード固定**：`<meta name="color-scheme" content="light">` と `:root{color-scheme:light}` の両方を書く。ダークの切りかえを書かない
10. 白基調。文章はです・ます調の普通の説明文（キャラクターの口調にしない）。文字は 14px 以上
11. 専門用語の説明欄を右に置く（狭い画面では引き出し）
12. 説明は文字だけにせず、動く図かイラストを入れる。数式より日常のたとえを先に
13. 強弱の色は、強いほど赤、弱いほど青（サーモグラフィと同じ。緑＝強いにしない）
14. 画面の右上に版を出す（`const VER="YYYY-MM-DDa"`。直すたびに上げる）

**授業の作り**
15. 正解しなくても次へ進める（答えたら正解と解説を出す）。答えずには進めない
16. 作業（ゲーム・データ集め）の最中は考えさせず、終わってから分析させる
17. 判定は「動作で」行う。ミッションの合格条件を作ったら、**合格するはずの状態で合格し、典型的な誤りで不合格になる**ことをテストで確かめる
18. まとめ画面の数（クリア数・点数・分母）は手で書かず、データから数える

**保存**
19. `localStorage` は失敗する前提で使う（ひな形の `store` が try/catch で包んである）。使えなくても最後まで動く
20. 保存の名前は `<フォルダ名>-v1`。保存の形を変えたら番号を上げる

**先生用**
21. URL の末尾に `#sensei` で先生用：全部のページへ飛べる・正解が見える・答えずに進める・小テストを何度でも受けられる・記録は生徒と別の箱
22. `N` キーで先生用メモ（ページの `note`）
23. **`#sensei` は鍵ではない。** ソースも先生用メモも全世界から読める。生徒に見せられないもの（定期考査の本番の問題・名簿・URL の鍵）を入れない

**公開**
24. 生徒の氏名・出席番号・成績・答案、学校の内部事情、鍵（スプレッドシートの URL など）を書かない。repo は全世界に公開されている
25. 直すのは本体（日本語名の .html）だけ。`<フォルダ>/index.html` は `build.py` の生成物
26. push（公開）は先生の確認を取ってから。Classroom にはファイルではなく URL を貼る

## 3. 制作手順

作業は repo のいちばん上（`build.py` がある所）で行う。初めての環境では `npm install`（jsdom と playwright）。

1. **設計を短く書く**（10行ほど）：ページの並び、問題の数と分野、シミュレーターのモデル式と定数とその出典、ミッションの合格条件、用語。モデルに選択肢があるときだけ先生に聞く。それ以外は進める
2. **ひな形を写す**
   ```bash
   cp .Codex/skills/kyouzai/template.html 音で距離を測る.html
   cp .Codex/skills/kyouzai/regression-template.js regression-oto.js
   ```
3. **データを書く**：本体の「★授業ごと」の所だけ。順番は `VER`・`FOLDER`・`TITLE` → `SECS` → `TERMS` → `MODEL` → `CH`・`Q`・`EXTRA` → `SIMS` → `PAGES` → `TEST`。使わない部品（問題・シミュレーター・小テスト）は `/*== 部品名 ==*/` から `/*== 部品名 おわり ==*/` までを消してよい（CSS と JS の両方）。「■共通」の所は直さない
   - 問題の答えに数を書くときは、`MODEL` から計算して書く（`a: MODEL.roundTrip(2, 20) * 1000`）。手で書いた数は食い違いのもと
   - 1つ選ぶ問題は、正解を `o` の先頭に書く。画面では位置が配り直される
   - まちがいの選択肢は、正解と同じくらいの長さで、似た考え方のものにする（長さで当てられないように）
4. **計算の検証を書く**：`regression-oto.js` の `CALC` に、教材のコードを使わずに計算し直した値を並べる。やり方は `verify-calc.md`。画面に出る数・問題の答え・解説の中の数・ミッションの合格条件を全部入れる
5. **確認スクリプトを通す**
   ```bash
   node regression-oto.js 音で距離を測る.html        # 「合格 n / 不合格 0」まで直す
   ```
6. **実ブラウザで確かめる**
   ```bash
   node .Codex/skills/kyouzai/check-browser.mjs 音で距離を測る.html --out /tmp/kyouzai-check/oto
   ```
   - `report.md` の NG を全部なくす。「注意」（14px 未満・44px 未満）も、生徒が使う部品なら直す
   - **画面写真は必ず自分の目で見る**。自動の点検は、重なり・見切れ・読みにくさ・図の分かりにくさを見落とすことがある（ひな形を作ったときも、スマートフォンで章の札がボタンに隠れていたこと、先生用の欄が白地に白い文字になっていたことを、写真を見て見つけた。どちらも見つけたあとで点検に足した）。最低限見るもの：各画面の大きさで最初のページ・シミュレーターのページ・問題に答えたあと・小テスト・まとめ
   - 先生用も見る：`--hash '#sensei'`
7. **直す**（4章の手順）。直したら 5 と 6 を全部やり直す
8. **公開の準備**（push はしない）
   - `VER` を今日の日付に
   - `build.py` の `PAGES` に1行：`("音で距離を測る.html", "oto/index.html", "メモ"),`
   - `python3 build.py`
   - `README.md` の「何をするもの」の表と「生徒に配るURL」の表と「ファイル」の表に1行ずつ
   - コミット（`[crocky] ` で始め、何を作ったかを日本語で）。push は先生の確認を取ってから
9. **報告**：作ったもの・URL（予定）・決めた既定値・検証の結果（合格数、実ブラウザの NG 数、見た画面写真）・未解決のことを短く

## 4. エラーを直す手順

1. **再現する**：NG の項目名、console のエラー文をそのまま控える。推測で直さない
2. **原因を1つに絞る**：jsdom なら `w.eval('st')` などで状態を見る。画面の崩れは、その画面の写真と `report.md` の部品名で場所を特定する
3. **直すのは本体だけ**。ひな形の「■共通」に原因があれば、本体ではなく `.Codex/skills/kyouzai/template.html` を直し、ひな形自身の確認（5章）を通してから本体に写す
4. **同じ失敗を捕まえる項目を1つ足す**（`regression-<フォルダ>.js` か `CALC`）
5. 3章の 5・6 を**全部**やり直す。一部だけ通して終わりにしない
6. 3回直しても通らなければ止めて、分かったこと・分からないこと・試したことを書いて先生に聞く

## 5. ひな形そのものを直すとき

ひな形は全部の新しい教材のもとになる。直したら、必ず両方を通す：
```bash
cd .Codex/skills/kyouzai
node regression-template.js template.html
node check-browser.mjs template.html --out /tmp/kyouzai-check/template
```
点検を足したら、**わざと誤りを入れた写しで、その点検が NG を出すこと**を確かめる（通るだけでは点検が働いている証拠にならない）。
すでに配った教材は、ひな形を直しても変わらない。変えるなら、教材ごとに別の作業として先生の確認を取る。

## 6. 既存の教材から借りるとき（よくできている所）

ひな形にない部品が要るときは、ここから借りる（読むだけ。既存のファイルは直さない）。

| 欲しいもの | 見る所 |

| 車などの物理（固定きざみ・乱数の種を固定したテスト・成功率で合否） | `自動運転への階段.html` の `physStep`、`regression-parking3.js` |
| 問題データの点検（正解の位置の偏り・長さの偏り・出題範囲外の語） | `regression-seigyo100.js` |
| 語群で答える小テスト（ステージ制・各語1回だけ） | `制御クイズ100.html` の `mkBank` |
