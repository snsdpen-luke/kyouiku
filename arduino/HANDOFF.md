## 1. 何を作っているか

高校の授業（1回3時間 × 2回）で使う、Arduino の教材ページ。

- **1つの HTML ファイル**（`arduino-kyozai-1.html`）に、課題20個が入っている。
- 生徒は **Windows PC の Arduino IDE** でコードを打って UNO に書き込む。
- 教材ページは **Chrome で開き**、USB で UNO とつなぐ（Web Serial）。UNO が送る文字を読んで、画面のシミュレータ（ランプ、時計、ゲームなど）を動かす。
- 課題11〜20 では、ページから UNO へも文字を送る（ゲームでぶつかった、など）。
- コードは大部分を見せて、**穴（A, B, C…）だけ生徒が考えて打つ**。コードはコピーできない。

### 決まっていること（先生が決めたこと）

| 項目 | 内容 |
|---|---|
| ボード | Arduino UNO R3 |
| 書き込み | Windows の Arduino IDE（Chromebook では IDE が動かないので使わない） |
| 教材ページ | Windows の Chrome（または Edge）で、ファイルを**直接**開く |
| 部品（1回目） | LED、タクトスイッチ、PC のスピーカー、サーボ SG90、超音波センサ HC-SR04 |
| ジョイスティック | **2回目**に回す（1回目には出さない） |
| コード | 大部分は用意。残りを生徒が考えて打つ。コピペ不可 |
| 配線の確認 | 画面で配線図を見る形 |
| 課題11〜20 | 部品を組み合わせた「作品」（ゲームやシステム）。生徒が「すごい」と思うもの |

### これまでの流れ（なぜ今の形か）

1. 最初は課題10個（LED → 画面 → 音 → 時計 → サーボ → 距離センサ）。
2. 11〜20 を追加。
3. さらに「作品」10個（21〜30）を追加。
4. 古い 11〜20（部品の練習）を**消して**、作品を 11〜20 に繰り上げた。
5. 作品の穴を 8〜10個に増やした → 難しすぎた → **半分（4〜5個）に戻した**。
6. ヒントを2段にした（言葉のヒント ＋「形を見る」ボタン）。

## 4. 使い方（授業で）

### 開き方

- HTML を**ダウンロードして、Chrome で直接開く**。アドレスが `file:///C:/...` になっていれば正しい。
- **Claude アプリの中のプレビューで開くと、USB が使えない**（「USB を使えない開き方です（SecurityError）」と出る）。
- それでもダメなら `chrome://settings/content/serialPorts` で、シリアルポートの使用を許可する。

### 接続

1. Arduino IDE で書き込む。
2. ページ右上の「UNO に接続」→ 一覧から UNO の COM を選ぶ。
3. **もう一度書き込むときは、先にページの「切断」を押す**（ページと IDE が同じ USB の口を取り合うため）。
4. IDE のシリアルモニタ・シリアルプロッタ、別タブの同じページが開いていると、つながらない。

### 切り替え

| 操作 | 効果 |
|---|---|
| 右上「むずかしさ」ボタン | 課題1〜10 の穴が増える（1行まるごとの穴）。PC ごとに記憶（localStorage `arduino-hard`） |
| URL の最後に `?hard` | 最初から「むずかしい」 |
| URL の最後に `?sensei` | 先生モード：穴に答えが入り、ヒントにも答えが出る |
| 「形を見る」ボタン | その穴の答えの形を出す（例：`hand == □□□□`） |
| 右下「試しに送る」欄 | UNO がなくても、`freq=440` などを打って画面を試せる |
| スペースキー／マウス | 課題12（ジャンプ）、課題13（パドル）を UNO なしで試せる |

## 6. 通信の決まり

速さは **9600**。1行ずつ送る。

### UNO → PC

形：`名前=数,名前=数` ＋ 改行（`Serial.println`）。数だけ（文字は不可）。読めない行はログに赤で「読めない形」と出る。

| 名前 | 意味 | 使う課題 |
|---|---|---|
| `led` | 0/1 ランプ | 5, 13 |
| `freq` ＋ `ms` | 音を1回鳴らす（ms 省略で 0.3秒）。例 `freq=880,ms=60` | 6, 12, 14, 15, 16, 17, 18, 20 |
| `tone` | 送り続ける間ずっと鳴る音（0 で止まる。0.4秒来ないと止まる） | 11 |
| `sec` `min` `hour` | 時計 | 7 |
| `dist` | 距離 cm | 9〜11, 13〜17, 19 |
| `angle` | サーボの角度 | 10, 16, 18 |
| `note` | 音の番号 0〜7 | 11 |
| `jump` | 1 でジャンプ | 12 |
| `pad` | パドルの位置 0〜100 | 13 |
| `guess` `target` | 答え合わせ | 14 |
| `sel` `ans` | 選んでいる答え／決定（1=○, 2=×） | 15 |
| `lock` | 1 でロックオン | 16 |
| `mole` `hand` `score` `left` `over` | もぐらたたき | 17 |
| `stop` `err` `level` | ピタッと止めろの結果 | 18 |
| `sw` | スイッチ 0/1 | 19 |
| `digit` `count` `miss` `open` | 金庫 | 20 |

（`bri` `time` `mode` は消した古い課題用。残っていても害はない）

### PC → UNO（課題12, 13, 15, 19）

UNO 側は `Serial.available()` と `Serial.read()` で1文字ずつ読む。送った文字はログに青で「→ UNO へ」と出る（未接続なら「届かない」と出る）。

| 課題 | 文字 | 意味 |
|---|---|---|
| 12 恐竜 | `h` / `r` | ぶつかった／新しいゲーム |
| 13 パドル | `b` / `0`〜`3` | ブロックをこわした／残りの命 |
| 15 クイズ | `o` / `x` / `n` | 正解／不正解／次の問題 |
| 19 リモコン | `S90\n` / `L128\n` / `B\n` | サーボ角度／LEDの明るさ（`Serial.parseInt()` で読む）／追加課題用 |

### 課題1つ分のデータ（`LESSONS` の1要素）

```js
{
  kind: "both",                 // "real" | "sim" | "both"（タブの色とラベル）
  tab: "14 距離当て",            // タブの文字。★番号も手で書いている。EXTRA のキーにも使う
  title: "距離当て探知機",
  goal: "…",                    // 「ゴール：」の後に出る
  wiring: () => fullSet(["sw", "led", "sonic"]),   // 配線図の HTML を返す関数
  code: `… if (diff <= {B}) { …`,  // {A} {B} … が穴
  answers: { A: "abs(d - target)", B: "1", … },
  hints:   { A: "d と target の差。abs( ) を使うと…", … },
  extra: NOTE_TABLE,            // 任意：ヒントの下に出す HTML（音の表など）
  more: "…",                    // 「できたら：」の追加課題。{B} と書くと穴の記号に合わせて直る
  sim: "finder",                // 右の画面。DRAW のキー。なければ real の確認チェック欄を出す
  real: ["…", "…"],             // sim がない課題の、実機の確認チェック項目
}
```

- 課題番号「課題○」は配列の順番から自動で付く。**タブの文字の番号だけは手で書いている。**
- 穴の記号は `{A}` 形式。`EXTRA` と `variant()` が穴を足したあと、**上から順に A, B, C… と付け直す**。

### 穴を足すしくみ（2種類）

- **`EXTRA`**（作品編用、いつも効く）：キーは `tab` の文字。`[コード中の文字, ヒント]` の並び。ページ読みこみ時に、その文字が**最初に出てくる所**を穴にする。今は 11, 15, 17, 20 に1個ずつ。
- **`HARD`**（課題1〜10用、むずかしいモードのときだけ）：キーは課題番号（1〜10）。しくみは EXTRA と同じ。`variant(L, i)` が毎回作る。
- 注意：探す文字が別の行の一部になっていないか確かめること（例：`speed = 1.0;` は `float speed = 1.0;` の中にもある）。

### コピー禁止

- コードとヒントは CSS `user-select:none`。
- `copy` `cut` `contextmenu` `dragstart` `selectstart` を止める。
- Ctrl+A で全選択してコピーしても、コピーの中身を「コードはコピーできません。自分で打とう。」に差しかえる（選択範囲にコード欄が入っているかを `containsNode` で判断）。
- 開発者ツールを使えば破れる。授業用としては十分、という判断。

### 画面（シミュレータ）のしくみ

- `handleLine(line)`：1行を `,` で分け、`名前=数` を `state` に入れる。`freq` なら `playTone()`。その後、今の課題の `SIMDATA[sim](got)` を呼ぶ（ゲームの出来事の処理）。
- `showLesson(i)`：表示を作り直し、`state` を `STATE0` に戻し、`SIMINIT[sim]()` でゲームを初期化。課題19 だけ `#ctrl`（スライダー）を出す。
- `frame()`：毎フレーム `DRAW[sim]()` を呼ぶ。
- ゲームの中身は変数 `G` に入れる（課題が変わると空にする）。
- 新しい `state` の名前を使うときは、**`STATE0` に足すこと**（`state` にない名前は読み捨てられる）。
- `drawDistLed` `drawServoOnly` `drawCounter` `drawBright` `drawStopwatch` `drawReaction` `drawGate` `drawAlarm` は、消した古い課題11〜20 の画面。今は使っていない（残してある）。

### 接続（Web Serial）

- `requestPort()` → `open({ baudRate: 9600 })`。失敗を2つに分けて表示する（開き方の問題 SecurityError ／ ポートが使用中）。
- 読み取り：`TextDecoderStream` で文字にして、改行ごとに `handleLine`。
- 書きこみ：`sendToUno()`。書きこみが重ならないよう Promise の列でつなぐ。

## 8. よくある作業の手順

### 課題を足す・消す・並べ替える

1. `LESSONS` の要素を足す／消す。
2. **`tab` の番号を全部書き直す。**
3. `EXTRA` のキー（tab の文字）を合わせる。
4. `HARD` のキー（番号）を合わせる。
5. ヒントや「できたら」の中の「課題○と同じ」などの番号を探して直す（`grep -n "課題[0-9]"`）。
6. タブの区切り（「作品 →」）は `LESSONS.forEach` の `if (i === 10)` で入れている。位置が変わったら直す。
7. 下の「確かめ方」を全部やる。答えファイルを作り直す。

### 穴を増やす・減らす

- 作品編：`EXTRA` に足す／消す。元からの穴は `code` の `{X}` と `answers` `hints` を直接直す。
- 課題1〜10 のむずかしいモード：`HARD` を直す。

### 新しい画面（sim）を作る

1. `function drawXxx() { … }` を書く（`clear()` `text()` `gauge()` `lamp()` `drawRuler()` `valText()` が使える）。
2. `DRAW` 表に `xxx: drawXxx` を足す。
3. 必要なら `SIMINIT.xxx`（初期化）と `SIMDATA.xxx = got => {…}`（行が来たときの処理）。
4. 新しい名前は `STATE0` に足す。

## 13. 2回目（ジョイスティック）— `src/arduino-kyozai-2.html`

2026-10-26 crocky 作成。先生の指示：「別のファイルにする。VRx と VRy を使い、段階的にジョイスティックをクリアしながら、いろいろな部品と組み合わせる」。

### 形式

1回目と同じ（穴埋め・コピー不可・ヒント2段・先生モード `?sensei`・むずかしいモード・試しに送る欄・Web Serial 9600）。
1回目の HTML から共通部分（CSS、`pin()` `uno()`、穴を足すしくみ、`variant()`、受信・音・接続、`gauge` `lamp` `valText` `drawRadar`、`sendToUno` `setTone`、画面の切り替え）をそのまま写し、課題と画面だけを新しく書いた。

1回目とのちがい：

- 課題番号は **21 から**（1回目の続き）。`const FIRST = 21` が番号の元。`HARD` のキーは「何番目か」（1 = 課題21 … 5 = 課題25）
- タブの区切り「作品 →」は 6 番目（課題26）の前
- 答えファイルの見出しはページの `KOTAE_HEAD` `KOTAE_WIRE` から作る（`make-kotae.mjs` を直した。1回目の答えファイルは前と1バイトも変わらないことを確かめた）
- `arduino-stub.h` に `A1` `tone` `noTone` を足した
- UNO がなくても、課題26・29 は矢印キー（29 はスペースでビーム）で遊べる

### 配線

| UNO | つなぐ先 | 使い始める課題 |
|---|---|---|
| A0 / A1 / D2 | ジョイスティック VRx / VRy / SW（+5V → 5V、GND → GND）。KY-023 型 | 21 |
| D6 | 抵抗 220Ω → LED | 23 |
| D9 | サーボ SG90（赤 5V、茶 GND） | 24 |
| D10 | ブザー（パッシブ）の ＋、－ は GND | 25 |
| D7 / D8 | 超音波センサ Trig / Echo | 26〜30 の表に入る（使うのは 27・30） |

部品は外さずに足していく。課題26〜30は配線を変えない（1回目の 11〜20 と同じ考え方）。
1回目のタクトスイッチ（D2）の代わりに、ジョイスティックの押しこみ（SW）を D2 に使う。
