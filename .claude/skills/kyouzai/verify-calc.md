# 計算の検証 — 教材の数を、教材の外で計算し直して突き合わせる

シミュレーターや問題の答えの数がまちがっていると、教材そのものが嘘になります。
画面が動いていても、数が正しいとは限りません。そこで、**教材のコードを使わずに同じ数を計算し直し**、`regression-<フォルダ>.js` の `CALC` で突き合わせます。

## 1. 決まり

1. **式は教材から写さない。** 教科書・データシート・公的な資料・自分で導いた式から、`CALC` の上に別に書く。写すと同じまちがいを二度書くだけになる
2. **出典を1行書く**（例：`// 音速の近似式 331.5+0.6T（理科年表）`）
3. **単位をそろえてから比べる**（ms と s、km/h と m/s、dB と倍）
4. **許す差 `tol` は理由のある大きさにする。** 式どおりなら `1e-9`。解説の「約11.6」のように丸めた数なら、丸めの幅（0.05〜0.1）

## 2. 何を突き合わせるか（全部）

| 対象 | 例 | `CALC` の書き方 |
|---|---|---|
| モデルの式 | 音速・往復時間・パルス数 | `actual: w => w.eval('MODEL.v(20)')` |
| 数で答える問題の正解 | `Q` の `a` | `actual: w => w.eval('QI.B1.a')` |
| 解説や説明文に書いた数 | 「約11.6 ms」「1/4」 | 文の数を `actual` に、独立計算を `expect` に |
| 画面の表示（読み取り） | 往復時間の表示 | 表示の関数を呼ぶか、表示の文字を読み取る |
| ミッションの合格条件 | 合格するはずの状態・しないはずの状態 | `ok({...})` を 1／0 にして比べる |
| ミッションが手の届く範囲で合格できるか | ボタンで作れる値を全部試す | ループで探して、見つかれば 1 |
| まとめの数の分母 | クリアできるステージの数 | `MISSIONS.length` と画面の分母 |

## 3. 説明とモデルが食い違わないか

**理論の式**（教科書の理想化）と、**現実に近い式**（シミュレーター）がずれることがあります。どちらも正しいのに、生徒が画面で確かめると説明と合わない、という形で教材が嘘になります。

例：電波の強さ。
- 自由空間（理論）：強さは距離の2乗に反比例する。距離が2倍で 1/4（−6dB）
- 屋内（現実に近い）：壁や家具で、指数が 2.5〜3.5 ほどになる。指数 2.8 なら、距離が2倍で約 1/7（−8.4dB）

説明・小テストが「1/4」、シミュレーターが指数 2.8 だと、生徒が測ったときに合いません。見つけたら、どちらに合わせるか、両方を見せて違いを教えるかを**先生に聞く**（授業の狙いで決まるため）。

`CALC` には、説明文に書いた比を、シミュレーターのモデルで計算したものと突き合わせる項目を入れておきます：
```js
// 説明「距離が2倍で 1/4」がモデルと合うか
{ name: '距離2倍で強さ 1/4（説明文）', actual: w => w.eval('10**((rssi(6)-rssi(3))/10)'), expect: 1 / 4, tol: 0.02 },
```

## 4. 乱数が入るシミュレーター

1. 乱数は種を固定できる形にする（`Math.random` を直接使わず、`rand()` を1か所に）
2. 1回の結果ではなく、**多くの回数の割合**で確かめる（例：見本の運転で40条件中9割以上成功、まちがった数字では失敗が出る）
3. 物理は固定きざみ（0.05秒）で進める。きざみが変わると結果が変わる作りにしない

手本：`自動運転への階段.html` と `regression-parking3.js`。
